# 냥냥클랜 배틀이력 수집기 · 한국 서버 검증판 v0.1

게임에서 **직접 연 클랜전 화면의 응답**을 PC에서 읽어 공격 후보를 추출합니다.
현재 한국 서버 계정으로 실측한 버전은 아닙니다. 정상 연결되더라도 게임 화면과
실제 수치가 일치하는지 한 번 대조해야 합니다.

## 윈도우에서 시작

1. ZIP을 **압축 해제**합니다. ZIP 안에서 바로 실행하지 마세요.
2. [Python 3.12 이상](https://www.python.org/downloads/windows/)을 설치합니다.
   설치 시 Python Launcher를 함께 설치합니다.
3. `1-install.cmd`를 실행합니다. 최초 한 번 필요한 구성요소를 설치합니다.
4. `2-start.cmd`를 실행하고 **1. 연결 주소 확인**을 선택합니다. 보고서가 브라우저에 열립니다.
5. 아래의 앱플레이어 프록시 연결 설정을 마친 뒤, 게임에서 **클랜전 상황판과 배틀이력**을 엽니다.
   **이 연결 확인 단계에는 인증서 설치가 필요 없습니다.** 암호화된 통신은 그대로 전달합니다.
6. 보고서를 새로고침하고, `연결 진단`의 `gameHosts`에서 실제로 연결된 게임 관련 서버를 확인합니다.
   `3-open-report.cmd`로 보고서를 다시 열 수도 있습니다. 주소가 불확실하면 `diagnostic.json`으로 확인합니다.
7. 수집을 마치면 수집기 창에서 `Ctrl+C`를 누르고 **앱플레이어의 프록시를 없음으로 되돌립니다.**

서버 주소를 확인했으면 `config.json`의 `hosts`를 해당 게임 호스트로 맞추고,
아래 HTTPS 인증서 설정 후 `2-start.cmd`의 **2. 배틀이력 추출**로 진행합니다.

게임 계정이나 비밀번호를 입력하는 단계는 없습니다. 사이트의 기존 기록을 바꾸거나
우리 사이트 서버로 전송하는 기능도 아직 포함하지 않습니다.

## 앱플레이어 연결

게임을 실행하는 기기에서 나가는 통신이 이 PC를 거쳐야 합니다. 앱플레이어별 설정
위치는 다르지만 안드로이드의 연결된 Wi-Fi 상세 설정에서 **프록시 → 수동**을 사용합니다.

- 같은 PC의 앱플레이어가 호스트 PC를 `10.0.2.2`로 제공하는 경우: 서버 `10.0.2.2`, 포트 `8877`.
- 연결되지 않거나 휴대폰에서 시험하는 경우: 아래 LAN 방식으로 연결합니다.
- 기기 내부의 `127.0.0.1`은 **기기 자신**이므로 PC 수집기 주소로 쓰지 않습니다.

### LAN 방식

1. `config.example.json`을 같은 폴더에 `config.json`으로 복사합니다.
2. PC에서 `ipconfig`로 현재 사용하는 사설 IPv4 주소를 확인합니다.
3. `config.json`의 `listen`을 그 PC 주소로 바꿉니다. 예: `192.168.0.12`.
4. 수집기를 다시 시작합니다.
5. 앱플레이어/휴대폰 프록시 서버에도 **같은 PC 주소**, 포트 `8877`을 적습니다.
   휴대폰은 PC와 같은 로컬 네트워크에 연결해야 합니다.
6. 윈도우 방화벽에서 연결을 막는 경우, 해당 프로그램의 사설 네트워크 연결을 허용합니다.

### HTTPS 인증서

**연결 주소 확인 모드에는 필요 없습니다. 배틀이력 추출 모드에서만 적용합니다.**

프록시가 연결된 **기기의 브라우저**로 `http://mitm.it`에 접속합니다.
Android용 인증서를 내려받아 기기가 제공하는 **CA 인증서 설치**에서 설치합니다.
이 인증서는 이 PC에서 생성하며 `.certs` 폴더에 보관됩니다.
다른 사람이 만든 인증서 파일을 가져올 필요는 없습니다.

브라우저의 `mitm.it`도 열리지 않으면 PC 주소·포트·방화벽부터 확인합니다.
브라우저는 연결되는데 게임만 인증서 오류가 나면, 그 앱플레이어에서 게임이 사용자
CA를 신뢰하지 않는 경우일 수 있습니다. **프록시를 해제해 게임 연결을 복구**하고,
앱플레이어 이름과 버전, `diagnostic.json`을 기준으로 다음 연결 방법을 확인해야 합니다.
이 검증판은 인증서 검사를 끄거나 게임 앱을 수정하지 않습니다.

## 결과 파일

실행할 때마다 `output/날짜-시간/`을 새로 만들어 이전 결과를 보존합니다.

| 파일 | 내용 |
| --- | --- |
| `report.html` | 추출한 공격 후보와 확인할 항목을 보는 화면 |
| `battle-history-review.json` | 닉네임·보스 번호·회차·피해량·공격 시각·명시된 이월 여부 등의 검토 자료 |
| `battle-history.csv` | 같은 공격 후보를 엑셀 등에서 볼 수 있는 자료 |
| `diagnostic.json` | 응답 형식·필드 이름·관찰된 클랜전 경로·실패 코드. 닉네임·계정 ID·인증 토큰 값은 제외 |

연결 주소 확인 모드의 진단에는 프리코네/카카오게임즈 관련 **호스트 이름·포트·연결 횟수만**
남습니다. TLS 복호화, 요청/응답 본문 저장은 하지 않습니다. 후보에는 로그인·패치 서버가
함께 나올 수 있으므로 후보 전체가 배틀이력 서버라는 뜻은 아닙니다.

**형식 확인을 요청할 때에는 `diagnostic.json`부터 보내면 됩니다.**
공격 후보가 0건이어도 어떤 연결/형식에서 멈췄는지 확인하는 데 사용합니다.
`.certs`, 원본 HAR, 인증 헤더, 계정 비밀번호를 보낼 필요는 없습니다.

검토용 JSON은 우리 사이트와 맞출 필드를 갖춘 **검증용 형식**입니다.
현재 사이트에 바로 가져오는 버튼은 없습니다. 실제 한섭 응답의 값과 범위를 확인한 뒤
사이트 연동 단계에서 명단 매칭과 순서 검증을 추가합니다.

## 수집 범위와 해석

- 과거 한섭 공개 구현에서 확인한 호스트 `live.pcr.kakaogame.com`을 기본값으로 사용합니다.
  현행 게임 API 호환성은 아직 확인되지 않았습니다.
  실제 API 호스트가 바뀌었다면 `config.json`의 `hosts`를 바꿔야 합니다.
- JSON을 우선 해석합니다. MessagePack과 pcr-exporter에 문서화된 구형 AES-CBC 형식도
  해석할 수 있습니다. 구형 형식은 수집기를 먼저 켜고 게임을 다시 시작해야 세션 IV를
  메모리에서 확인할 수 있습니다. IV는 출력하거나 파일로 저장하지 않습니다.
- 알려진 읽기 응답인 `/clan_battle/top`의 `damage_history`와
  `/clan_battle/mylog`의 **`actual_logs`만** 공격 후보로 취급합니다.
  `/index.php/` 접두사가 있는 한섭 형태도 처리합니다.
- 공개 택틱 로그 `battle_log_list`, 모의전·트레이닝 로그, 개인 합계 순위,
  캐릭터별 피해량 보고서는 개별 클랜원의 실전 공격으로 가져오지 않습니다.
- 마이 로그의 원본 형식에 닉네임·공격 시각이 없으면 빈 값으로 남깁니다.
  `battle_time`은 공격한 시각이 아니라 전투 시간일 수 있어 날짜로 바꾸지 않습니다.
- **격파했다고 이월을 사용한 것은 아닙니다.** 이월 사용 플래그가 응답에 명시된 경우만
  값을 채웁니다. 시작 잔여 시간이 짧다는 이유만으로도 이월을 확정하지 않습니다.
- 현행 한섭의 `clan_battle_mode` 코드 의미는 미확인입니다. 값이 있으면 확인 대상으로 표시합니다.
- 단계가 없으면 임의로 계산하지 않습니다. 사이트의 해당 월 회차 설정으로 계산할 단계입니다.
- 클랜 ID·개최 ID·원본 기록 ID가 있는 같은 응답은 중복 제거합니다.
  ID/범위가 부족한 동일한 값은 별개 공격일 수 있어 삭제하지 않고 중복 후보로 남깁니다.
  같은 초에 나온 기록도 순서를 확정하지 않고 표시합니다.
- 서버가 이 화면에 내려준 기록까지만 수집합니다. 과거 기록 전체나 30명 전체 이력을
  제공한다고 보장하지 않습니다. 수집기를 켠 동안 화면을 다시 열면 새 응답을 추가로 읽습니다.
- 아직 모르는 클랜전 경로는 경로 이름만 진단에 남깁니다. 전투 실행·요청 재전송·
  자동 로그인·주기적인 API 호출은 하지 않습니다.

## 이미 받은 JSON 또는 HAR 확인

수집 도구에서 내보낸 파일이 있다면 게임에 다시 연결하지 않고 확인할 수 있습니다.
원본 파일은 이 PC에서만 읽습니다. HAR에는 다른 통신과 인증정보가 포함될 수 있으므로
원본 대신 수집기가 만든 `diagnostic.json`을 공유하세요.

```bat
.venv\Scripts\python.exe probe.py convert "C:\경로\응답.json"
.venv\Scripts\python.exe probe.py convert "C:\경로\capture.har"
```

JSON 입력의 기본 경로는 `/clan_battle/top`입니다. 마이 로그는
`--endpoint /clan_battle/mylog`를 붙입니다. HAR에서는 설정된 호스트와 읽기 경로의
응답만 골라서 처리합니다. 암호화된 HAR에서 세션 IV를 확보하지 못하면 해석되지 않습니다.

## 게임 연결 없이 예제 실행

```bat
.venv\Scripts\python.exe probe.py convert example.synthetic.json
```

**이 예제는 모두 합성 데이터입니다.** 보고서에도 합성 예제라고 표시합니다.
예제 성공을 한섭 추출 성공으로 판정하지 않습니다.

## 개발 검증

```bat
.venv\Scripts\python.exe -m unittest -v test_probe.py
.venv\Scripts\python.exe integration_test.py
```

JSON / MessagePack / 구형 AES 및 IV 검증, 중복·범위·불명확한 값 처리,
인증정보 저장 제외, HTML·CSV 이스케이프, 실제 mitmproxy HTTPFlow 무변경 처리를 검증합니다.
통합 테스트는 **PC 내부의 합성 HTTP 서버**를 프록시로 통과시킵니다.
실제 한국 게임 서버나 사용자 계정에 접속하지 않습니다.

## 참고한 공개 구현

- [sokcuri/cyutils · Host.ts](https://github.com/sokcuri/cyutils/blob/234333a9f60fdb15f22c6cc783fc66472f7c8042/src/priconne/Host.ts)
  / [ApiService.ts](https://github.com/sokcuri/cyutils/blob/234333a9f60fdb15f22c6cc783fc66472f7c8042/src/priconne/ApiService.ts):
  과거 한섭 호스트·`/index.php/` 경로·JSON 응답 근거. 호스트 파일은 2020년 자료입니다.
- [FabulousCupcake/pcr-exporter](https://github.com/FabulousCupcake/pcr-exporter):
  프록시 방식과 구형 wire format 참고. 2023년 보관 처리된 프로젝트입니다.
  본 도구는 해당 Electron 앱을 재배포하지 않으며 현재 한섭 지원을 가정하지 않습니다.
- [cc004/autopcr의 모델](https://github.com/cc004/autopcr/tree/main/autopcr/model):
  알려진 응답 필드와 개인·공개·모의 로그 구분 참고. 한섭 현재 형식의 증거는 아닙니다.
- [mitmproxy 공식 문서](https://docs.mitmproxy.org/stable/):
  프록시·인증서·읽기 이벤트 처리와 호스트 제한.

패키지에는 소스와 합성 예제만 포함합니다. 게임 계정 데이터나 인증서 개인키는 포함하지 않습니다.
