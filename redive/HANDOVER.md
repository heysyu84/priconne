# Re²:Dive 운영 화면 인수인계

공개 화면은 `docs/index.html`, 기존 화면은 `docs/legacy.html`, 새 코드 원본은 `redive/`입니다. 상단 이동 버튼은 https://priconne.pages.dev/ 와 https://priconne.pages.dev/legacy.html 을 사용합니다.

## 저장 경로

공개 두 화면은 원래 `nyang-clan-manager.heysyu457310.chatgpt.site` API의 같은 자료를 읽고 저장합니다. 기존 비밀번호와 세션을 재사용하며 암호·인증 설정은 변경하지 않았습니다. `public/legacy-codec.mjs`와 `legacy-shared-client.mjs`, `src/pages-bridge.js`가 연결합니다. 초기 자료를 운영 서버로 자동 이관하거나 덮어쓰는 작업을 추가하지 마세요.

원본 API는 현재 월과 과거 월 아카이브를 나눕니다. 변경하지 않은 월은 쓰기 요청에서 제외하고, 이전 화면 전용 필드·기록 ID·정수 피해량·가산점·숨김·삭제함·명단 이력·수상 횟수를 보존해야 합니다. `check-migration.mjs`는 원래 라우트의 SQLite 모의 서버에서 양방향 동기화와 충돌을 검증합니다.

비공개 Sites 프로젝트 `appgprj_6add0796ed548191b984b67f12cf7f2a`는 개발 시제품이며 별도 D1입니다. 공개 API 메타가 없는 환경에만 기존 Sites 방식이 적용됩니다.

## 유지할 사용자 요구

- 별도 지시가 없으면 새 화면을 수정합니다. 기능을 임의로 생략하지 않습니다.
- 클랜전 탭 순서는 상황판·대시보드·배틀로그입니다. 상황판은 필요한 진행 정보만 HUD로 표시합니다.
- 제목은 크게·굵게, 링크와 버튼은 색·박스·명암으로 구분합니다. 외부 링크 화살표는 사용하지 않습니다.
- 대시보드는 짧은 타수 표기, 이월 초는 실제 격파 로그와 기존 공식으로 계산합니다. 일반·이월 박스 크기는 동일하게 유지하고, 이름·잔여·이월 정렬은 표 제목에서 전환합니다.
- 표의 이름은 테두리 없는 글자 링크로 표시합니다. 표 본문과 이름의 글자 크기를 맞추되 모바일 명단의 UID·가입월 한 줄 배치는 유지합니다.
- 한 줄 표 본문은 기록 유무와 관계없이 34px 높이·위아래 3px 여백으로 맞춥니다. 대시보드 일반·이월·미사용 내용의 높이는 공통 변수(웹 26px, 모바일 24px, 좁은 모바일 23px)를 사용합니다. 여러 줄 명단·명예의 전당·보스 통계는 6px 여백과 자연 높이를 유지하고 폰트·가로폭은 줄이지 않습니다.
- 수치 축약은 상황판·그래프, 택틱 기대딜, 상위 기여도 기록의 만 단위만 허용합니다. 순위는 전체 숫자입니다.
- 배틀로그 편집은 행 내부의 검색·숫자·이월타 체크박스로 저장합니다. 일반·격파·관통 유형은 자동 판정하며 드롭다운으로 직접 고르지 않습니다. 행 끝에서 이동·삭제·앞뒤 추가를 조작하며 새 기록도 같은 표 안에 추가합니다. 이동과 삽입은 화면의 오름/내림 순서를 실제 등록 순서로 변환해야 합니다.
- 등록 검색의 ↑↓는 결과 선택, 입력 경계의 ←→는 필드 이동입니다. 피해량에서 Tab은 가산점을 건너 이월 사용으로 이동하고 Enter 등록 성공 시 이름칸으로 돌아갑니다. 영문 원문과 직접 일치하는 이름을 한글 자판 변환 결과보다 먼저 정렬합니다. IME 조합 중에는 Enter·방향키를 가로채지 않습니다.
- 명단·순위 페이지 나누기 금지. 공격 기록은 50건씩. 모바일 순위는 하나의 정렬 가능한 표, 웹은 지표별 표입니다.
- 게임·택틱은 4단계가 마지막입니다. 3단계 추천 자료는 남기되 4단 진입 시 자동 숨김을 지원합니다.
- SET와 본문은 같이 표시하며 모바일은 줄바꿈합니다. A는 AUTO입니다. 진행 행 표시는 포커스와 무관하게 기기에 유지합니다.
- 택틱 추가·수정의 본문 붙여넣기는 기본으로 펼치고 창 전체 가로폭·기본 10행을 사용합니다. 캐릭터명 일괄 입력은 IME 조합 중에도 5명이 정확히 일치하면 즉시 적용하고, 조합 종료 시 같은 편성을 다시 적용해 수동 성급을 초기화하지 않습니다.
- 이월 택틱 목록 제목과 목록 닫기 사이의 시간대 선택은 전체·20초대·30초대·40초대·50초+입니다. 필요 이월시간 기준 20~29·30~39·40~49·50초 이상으로 보스 필터와 함께 적용하고, 미입력 기록은 전체에 남깁니다. 열람자도 사용하며 공용 자료에는 저장하지 않습니다.
- 조합 펼치기는 같은 카드 안에서 본문만 확장합니다. 필요 이월 초는 메모와 분리합니다. 추천분배는 선택 후 비우기로 전환하고 선택 수·복사·닫기를 상단에 둡니다.
- 상단 접속자 수는 기존 API와 동일한 브라우저 식별자를 사용합니다. 화면을 다시 그려도 마지막 접속 수를 유지합니다.
- 관리자 기능을 클라이언트 버튼만으로 허용하지 않습니다. 공개 API의 비밀번호 검증이 필수입니다.
- 현재 사용자 지시로 스크린샷 확인 없이 적용합니다. 기능·키보드 이벤트·공용 데이터 보존 검증과 배포 상태 확인은 진행합니다. 운영 데이터에 시험 기록을 쓰지 않습니다.

## 재빌드

`redive/`에서 `node scripts/prepare-server.mjs`로 브라우저 묶음을 만들고, 저장소 루트에서 `node clan-battle/scripts/build-pages.mjs docs`를 실행합니다. 원래 루트 자산을 지우지 마세요. 공개 빌드는 `compact/` 자산 경로와 공용 API 메타를 자동으로 설정합니다. 미래 보스는 기존 자동 갱신 JSON을 사용하며 수동 수정이 우선합니다.

검증 명령과 출처는 README에 있습니다. 새 캐릭터는 위치·별칭 자료에 추가하고 `build-character-reference.mjs`로 생성합니다. 수리아는 Summer Clear(135301), 수밀리아는 Summer Emilia(131901)입니다.


## 2026-10-28 화면·아카이브 보완

- 최초 렌더 전에 작성 모드를 잠급니다. 캐시가 있어도 공용 자료 적용 전에는 관리 기능을 그리지 않습니다.
- 현재 일차는 시작일과 오전 5시(KST)를 기준으로 계산합니다. 기본 일차는 자동이며, 사용자가 설정에서 고른 수동 일차만 기기에 유지합니다.
- 숨김 해제 시 버튼의 유일한 ID를 확인한 뒤 원래 분류로 이동해 복귀한 택틱을 선택합니다. 이월 시간·보스 필터를 초기화하며 보스별 정렬을 유지합니다.
- 기대딜 스피너는 0.1억 간격입니다. 기존 소수 둘째 자리 피해량과 직접 입력 정밀도는 보존하고, 음수 저장은 차단합니다.
- CSV 버튼은 제거하고 인쇄는 관리자 모드에서만 제공합니다. 기존 화면에도 같은 표시 규칙을 적용합니다.
- 2024~2025 원본 수치와 읽기 전용 저장 방식을 유지합니다. 월 선택·월별 요약·수상 표기를 공통 양식으로 통일하고 역사적 1·5단계도 표시합니다. 원본 DB에 이미 포함된 수상 횟수를 다시 합산하지 않습니다.
- 기록·통계의 아카이브는 `src/clan-archive.js`에서 원본 DB 연혁을 정리합니다. 인원수 관련 사항은 넣지 않습니다.
- 추가 검증: `node scripts/check-archive-startup.mjs`. 스크린샷은 이번 사용자 지시로 생략했습니다.

- 명예의 전당은 월별 수상·수상 횟수 하위 보기로 구성합니다. 이전 `#records/hall` 주소도 `#records/history/counts`로 연결합니다. 연혁의 메코 표기는 메이코패스로 통일합니다.
- 아카이브는 사이트 자체의 클랜 연혁으로 서술합니다. 공개 화면에 원본·원본 DB 같은 복제·이관 안내나 원본 DB 버튼을 넣지 않습니다. 출처 추적 정보는 코드에 보존합니다.

## 2019~2023년 이력 추가 이관

- `public/history-2019`부터 `history-2023`까지 54개월을 추가했습니다. 45개월 클랜 상세·2개월 개인 기록·7개월 순위만 보관이며 총 공격 31,850건입니다. 기존 2024~2026년 및 운영 API 자료는 수정하지 않았습니다.
- 정규화 도구는 `scripts/import-historical-resumes.py`입니다. 입력은 커넥터로 읽은 메타데이터와 경계가 지정된 범위 값, 기준 DB의 `monthlyHistory`입니다. 공격의 정수 피해량과 시트의 기여도·인게임 정밀도를 보존하며 조회 일차 합계와 대조합니다.
- 2019년 11·12월은 슈 개인 이력만 남아 있으므로 클랜 전체·클랜 순위처럼 집계하지 않습니다. 유실된 월은 알려진 순위만 표시하고 공격·점수를 0으로 채우지 않습니다.
- 2020년 4월은 모든 타격이 1일차로 변환돼 있고 당시 일일표가 비어 있으므로 일차를 추정하지 않고 월 누적으로 표시합니다.
- 2020년 6월은 저장된 순위가 3일차 조회이며, 전체 공격으로 기간 누적을 복원했습니다. 10월은 944건이 남은 다른 보관본을 사용했습니다. 두 달의 기존 수상 기록은 중간 일차 집계와 일치하므로 월 전체 순위와 차이를 안내하고 기존 수상 횟수를 보존합니다.
- 과거 기록의 기간·필터·그래프·PDF는 각 월의 실제 일수를 사용합니다. PDF는 당시 단계와 개인 기록 범위, 일차 미보관도 반영합니다.
- 검증은 `node scripts/check-historical-resumes.mjs`이며 CI에서 자동 실행합니다. 전 월 데이터 합계·필터·누락 상태·원래 자료 보존과 PDF의 1페이지 좌표 범위를 검사합니다. 사용자 지시로 스크린샷 검사는 생략했습니다.


## 2026-10-28 설거지 격파 이후 이월 입력

- 나르의 5일차 35회차 3넴 격파는 정확히 남은 HP를 입력한 정상 기본 3타째이며, 엔진에는 미사용 이월이 생성되어 있었다.
- 입력 중 공용 문서 적용을 보류하는 기존 동작 때문에, 다른 창의 새 격파가 아직 반영되지 않은 입력창에서 이월 없음으로 거부되는 경우를 재현했다. 이월 부족으로 신규 입력이 막히면 최신 문서를 읽고, 로컬 변경·월·편집 권한이 그대로일 때만 보존한 입력값으로 한 번 재검사한다. 새 로컬 변경은 덮어쓰지 않는다.
- 격파 앞에 삽입하려는 경우에는 보유 이월 없음과 구분하여 격파 뒤에 추가하라고 안내한다. 실제 사용자의 최초 입력 경로를 확정할 클릭 기록은 없다.
- 시간 미상 이월은 대시보드에 ★로 표시하며 시간 추정은 이월 존재 여부를 결정하지 않는다. 입력한 남은 시간이 있으면 해당 시간을 우선 표시한다.
- 검증: check-cleanup-carry.mjs (6), check-inline-logs.mjs (7), check-shared-client.mjs (11). 스크린샷 검사는 사용자 요청대로 생략했다. 실제 공격은 추가하지 않았다.
